# Skill And Source Synergy

Цель: каждый скилл должен закрывать свою зону, а не спорить с другими.

## Иерархия решений

1. `landing-page-high-conversion` решает, что страница должна продавать и в каком порядке.
2. `landing-source-forensics` собирает evidence-rich baseline в исходном проекте: screenshots, files, tokens, assets, commands and risks.
3. `landing-dossier-schema` гарантирует, что входной dossier полный и проверяемый.
4. `design-taste-frontend` решает, как избежать шаблонного AI-дизайна.
5. `landing-copy-offer-audit` проверяет promise, CTA, proof, objections и видимую copy.
6. `landing-proof-integrity-gate` verifies, rephrases, backlogs or rejects claims, metrics, testimonials, logos, reviews, screenshots, demo data and generated proof assets before visual polish.
7. `landing-brand-dna-preservation` решает, что в текущем лендинге preserve/evolve/remove/introduce/protect before references overwrite identity.
7. `landing-reference-source-catalog` выбирает правильные source lanes before search: landing galleries, SaaS examples, product-flow sources, visual galleries, motion references, CRO evidence, anti-references and access caveats.
8. `landing-reference-research` приносит реальные references и объясняет, что из них брать.
9. `landing-thematic-reference-mining` отделяет direct, adjacent, analogous, flow, visual, motion/component and anti references and requires closeness reasons.
10. `landing-reference-scoring` ранжирует references по product fit, section fit, visual fit, motion value, implementation risk and source safety.
11. `landing-inspiration-synthesis` переводит scored references в concrete section decisions, motion, assets and anti-copy boundaries.
12. `landing-motion-reference-mining` переводит real motion references into section-level motion candidates with borrow/transform/do-not-copy, fallback and library implications.
13. `landing-motion-safety-gate` assigns motion safety verdicts before recipes/storyboard: reduced motion, mobile comfort, Core Web Vitals, layout stability, dependency weight and implementation risk.
12. `landing-evidence-pack` сохраняет screenshots, references, assets и decision log.
13. `landing-visual-evidence-capture` фиксирует desktop/mobile/hero screenshots в manifest.
14. `landing-visual-benchmark` сравнивает текущую страницу с references и выдает visual gaps.
15. `landing-visual-direction` фиксирует style tile: tokens, surfaces, composition and section style rules.
16. `landing-section-patterns` выбирает конкретные section patterns and visible storyboards.
17. `landing-section-storyboard` связывает copy, visual style, reference, pattern, asset, motion, component and QA in a per-section canvas.
18. `landing-asset-art-direction` планирует hero, screenshots, images, video, 3D и GLB/WebGL assets.
19. `landing-asset-production` turns asset ideas into a concrete production queue with prompts, paths, alt text, performance and QA.
20. `landing-motion-recipes` выбирает конкретные section-level recipes from accepted motion references before detailed storyboard.
21. `landing-motion-storyboard` превращает recipe в точные motion specs и fallbacks.
22. `landing-responsive-viewport-storyboard` turns section, asset and motion plans into desktop, tablet, mobile and wide viewport frames before implementation.
23. `motion-component-source-map` выбирает источник компонентов/эффектов.
24. `motion-primitives-catalog` and `33-motion-primitives-source-map.md` выбирают exact Motion Primitives items only when a focused motion component beats native CSS or existing components.
25. `magic-ui-catalog` and `34-magic-ui-source-map.md` выбирают exact Magic UI items only when a strong marketing effect is earned by the section.
26. `aceternity-ui-catalog` and `35-aceternity-ui-source-map.md` choose exact Aceternity UI components or reference-only blocks with license/access and adaptation gates.
27. `tailark-section-catalog` and `36-tailark-section-source-map.md` choose exact Tailark public blocks or reference-only Pro/page patterns with access, registry, adaptation and stale-sitemap gates.
28. `shadcnblocks-catalog` and `37-shadcnblocks-source-map.md` choose exact free/pro shadcnblocks blocks, components, pages or reference-only patterns with access, registry, license and adaptation gates.
29. `micro-component-source-catalog`, `kibo-ui-catalog` and `38-micro-component-source-map.md` choose exact Kibo UI, Origin/Coss or similar micro-components with endpoint, dependency, license, keyboard/focus, mobile and adaptation gates.
30. `react-bits-catalog` and `39-react-bits-source-map.md` choose exact React Bits animated components with `TS-TW` variant, dependency, heavy-runtime, mobile, fallback and performance gates.
31. `pacekit-gsap-catalog` and `40-pacekit-gsap-source-map.md` choose exact PaceKit GSAP items only when GSAP choreography is justified, with runtime, fallback, mobile and performance gates.
32. `cult-ui-catalog` and `41-cult-ui-source-map.md` choose exact Cult UI textured/product-widget details with style, dependency, mobile and adaptation gates.
33. `reui-catalog` and `42-reui-source-map.md` choose exact ReUI app/product UI items with free/pro, license, keyboard/focus, mobile and dependency gates.
34. `twenty-first-dev-catalog` and `43-21st-dev-source-map.md` choose 21st.dev references or exact community components with page, command, CDN registry, license, dependency, mobile and QA gates.
35. `kokonut-ui-catalog` and `44-kokonut-ui-source-map.md` choose exact Kokonut UI public components with MIT/pro, motion, mobile and QA gates.
36. `mvpblocks-catalog` and `45-mvpblocks-source-map.md` choose exact MVPBlocks blocks, templates or text animations with endpoint, CLI, license, dependency, mobile and QA gates.
37. `smoothui-catalog` and `46-smoothui-source-map.md` choose exact SmoothUI components or blocks with endpoint, MIT, dependency, mobile, reduced-motion and broken-blocks-API gates.
38. `hextaui-catalog` and `47-hextaui-source-map.md` choose exact HextaUI app/SaaS proof blocks with endpoint, MIT, dependency, HTML-doc caveat, mobile and demo-data gates.
39. `skiper-ui-catalog` and `48-skiper-ui-source-map.md` choose exact Skiper UI motion details with endpoint, terms/access, broken-preview, dependency, reduced-motion, mobile and anti-copy gates.
40. `eldora-ui-catalog` and `49-eldora-ui-source-map.md` choose exact Eldora UI product proof, device mockup, text motion, background and small section items with endpoint, MIT, dependency, performance, reduced-motion, mobile and anti-template gates.
41. `blocks-so-catalog` and `50-blocks-so-source-map.md` choose exact Blocks.so app/product proof blocks with endpoint, MIT, duplicate-entry, dependency, demo-data, accessibility, mobile and anti-fake-proof gates.
42. `intent-ui-catalog` and `51-intent-ui-source-map.md` choose exact Intent UI React Aria components, controls and blocks with endpoint, MIT, dependency, example-page, accessibility, mobile and anti-bulk-install gates.
39. `11-component-source-registry.md` проверяет, откуда брать блок/компонент и какие риски.
40. `ui-audit` проверяет, стало ли лучше визуально и UX-wise.
41. `details-that-make-interfaces-feel-better` полирует micro-interactions.
42. `layers-*` помогает разложить продукт, пользователя, поведение, surface и flow.
43. `Animate UI catalog` плюс `17-animate-ui-full-site-map.md` используются точечно для компонентов, не как "установить все".
44. `landing-plan-tooling` создает папку проекта из `_template` и проверяет минимальную полноту плана.
45. `landing-implementation-task-graph` превращает storyboard, assets, motion and style tile в ordered build graph with blockers and evidence.
46. `landing-change-traceability` connects every major change to source evidence, references, brand decisions, tasks and QA before self-review.
47. `landing-plan-self-review` критикует сам план before implementation: generic language, weak references, vague motion, missing visible decisions.
48. `landing-implementation-handoff` превращает готовый план в prompt для implementation agent.
49. `landing-presentation-review` проверяет implemented page по screenshots/live preview на first impression, hierarchy, credibility, distinctiveness, motion polish, asset quality and mobile presentation.
50. `landing-final-qa` проверяет implemented page по screenshots, accessibility, performance, motion and plan compliance.
51. `GSAP/Three/WebGL/Blender` включаются только если brief требует сильной motion/3D сцены.

## Синергия по задачам

### Быстрый простой SaaS landing

- Structure: `landing-page-high-conversion`
- Copy/offer: `landing-copy-offer-audit`
- UI base: shadcn/ui + Tailwind v4
- Motion: Motion Primitives или Animate UI
- References: SaaS Landing Page + Saaspo + Land-book + 1-2 direct competitors
- Source routing: `landing-reference-source-catalog` + `52-reference-gallery-source-map.md`
- QA: `design-taste-frontend` + `landing-visual-benchmark` + `ui-audit`

### AI/tech/product landing

- Structure: `landing-page-high-conversion`
- Visual direction: `design-taste-frontend`, avoid default AI-purple
- Motion: `landing-motion-storyboard`, Animate UI, Magic UI, Motion Primitives
- Optional 3D: Three.js/WebGL if it carries product meaning
- References: Awwwards for interaction, 21st.dev for component discovery

### Premium consumer/product landing

- Structure: `landing-page-high-conversion`
- Visual direction: `design-taste-frontend`, avoid beige/brass default unless brand demands it
- Assets: `landing-asset-art-direction`, real product photos or generated product imagery
- Motion: subtle product reveal, tactile CTA, image hover
- References: Land-book by industry/style, Recent for packaging/branding cues

### Creative/agency landing

- Structure: more editorial, but still one primary CTA
- Visual direction: higher DESIGN_VARIANCE, higher MOTION_INTENSITY
- Motion: `landing-motion-storyboard`, GSAP sticky-stack or horizontal-pan only when storytelling needs it
- References: Awwwards + Recent + Codrops
- QA: strict reduced motion and mobile checks

## Conflict Rules

If two sources disagree:

1. Conversion clarity beats visual trick.
2. Accessibility beats animation.
3. Real product/story beats decorative effect.
4. Existing brand/SEO/analytics beats redesign fantasy.
5. `taste-skill` final pre-flight beats component-library defaults.

## Component Source Order

1. Existing project components.
2. Native Tailwind/CSS for layout.
3. shadcn/ui for owned primitives.
4. Animate UI for animated/headless primitives.
5. Motion Primitives for focused motion details.
6. Magic UI for landing effects when they fit the brief.
7. Aceternity/Tailark/shadcnblocks for block inspiration or exact gated blocks, adapted not pasted blindly.
8. Coss UI/Base UI for accessible form/overlay primitives.
9. React Bits only for one earned memorable animation or background, with heavy-runtime gate.
10. PaceKit GSAP only when GSAP sequencing/choreography is explicitly accepted.
11. Cult UI only for exact textured/product-widget details after style and dependency gates.
12. ReUI only for credible app/product UI details after access/license and keyboard/focus gates.
13. 21st.dev reference-first for community component discovery, exact install only after page, command, registry, license and dependency gates.
14. Kokonut UI only for exact small public shadcn-compatible details after MIT/pro and motion gates.
15. MVPBlocks only for exact section blocks or template references after endpoint, CLI, license, dependency and adaptation gates.
16. SmoothUI only for exact animated controls, AI/product proof details, text effects or small blocks after endpoint, MIT, dependency, broken-blocks-API, reduced-motion and mobile gates.
17. HextaUI only for exact app/SaaS proof blocks after endpoint, MIT, dependency, HTML-doc caveat, demo-data and mobile gates.
18. Skiper UI only for exact uncommon motion details or reference-only inspiration after official registry, terms/access, broken-preview, dependency, reduced-motion and anti-copy gates.
19. Eldora UI only for exact device/product proof, text motion, backgrounds or small blocks after endpoint, MIT, dependency, performance, reduced-motion, mobile and demo-data gates.
20. Blocks.so only for exact app/product proof blocks after endpoint, MIT, duplicate-entry, dependency, demo-data replacement, accessibility and anti-fake-proof gates.
21. Intent UI only for exact accessible app controls/forms/tables/overlays/blocks after endpoint, MIT, React Aria dependency, example-page, accessibility and mobile gates.
18. GSAP custom code only for real scroll choreography.
19. Three.js/WebGL/Blender only when the 3D object is central.

## Tooling Flow

1. In the source project, use `landing-source-forensics` or `24-source-dossier-forensics.md`.
2. Run `node scripts/create-landing-plan.mjs <project-slug> --dossier path/to/landing-source-dossier.md`.
3. Run `node scripts/check-source-dossier.mjs path/to/landing-source-dossier.md`.
4. Fill all required project files and the `evidence/` manifests.
5. Run `node scripts/check-landing-plan.mjs <project-slug>`.
6. Fix failures before implementation.

## Install Rule

Before installing any package:

- check `package.json`;
- check license/source;
- check whether it duplicates installed tools;
- write why this source is needed;
- install the smallest exact component/package;
- add reduced-motion fallback if animated.
