# Магазин

Практический модуль для проектирования и сборки продающих сайтов, где пользователь не просто читает лендинг, а выбирает товар или услугу, оформляет заказ, оплачивает, получает подтверждение и может вернуться к заказу.

Поддерживаемые режимы:

- `catalog` — обычный интернет-магазин: каталог, карточка товара, корзина, доставка, оплата;
- `pizzeria` — пиццерия, ресторан, доставка еды: адрес или ресторан, меню, модификаторы, время, заказ, трекинг;
- `booking` — услуги по записи: услуга, специалист, слот, депозит или оплата, подтверждение, перенос или отмена;
- `quote` — услуги с предварительным расчётом: квалификация заявки, вводные данные, обещание срока ответа, смета, согласование;
- `hybrid` — только когда бизнес действительно совмещает независимые потоки, например товары и запись. Потоки проектируются отдельно и сходятся только в общей оболочке бренда.

## Главный принцип

Маркетинговая страница и коммерческий поток — не одно и то же. Hero создаёт интерес, но продажу завершает непрерывная цепочка:

```text
намерение → выбор → конфигурация → цена и условия → корзина/слот → оплата/заявка → подтверждение → выполнение → повтор
```

Нельзя считать сайт магазином, если есть только красивые секции и кнопка «Купить», но отсутствуют состояния цены, наличия, ошибок, оплаты и подтверждения.

## Быстрый старт

Создать рабочую папку проекта:

```powershell
node "магазин/scripts/create-project.mjs" pizza-demo --mode pizzeria
```

Допустимые режимы: `catalog`, `pizzeria`, `booking`, `quote`, `hybrid`.

Затем заполнить файлы в `магазин/projects/<slug>/` в таком порядке:

1. `01-brief.md` — бизнес, аудитория, география, ассортимент, конверсия и ограничения;
2. `02-flow-map.md` — основной и аварийные пользовательские потоки;
3. `03-page-blueprint.md` — маршруты, секции и мобильная композиция;
4. `04-commerce-state-model.md` — сущности, состояния и серверные инварианты;
5. `05-copy-proof-and-trust.md` — оффер, доказательства, условия и юридические данные;
6. `06-implementation-plan.md` — файлы, интеграции, события и порядок реализации;
7. `07-qa-report.md` — фактические проверки;
8. `08-reference-board.md` — только релевантные референсы с решением «взять/изменить/не копировать».

Проверить полноту:

```powershell
node "магазин/scripts/check-project.mjs" pizza-demo
```

## Обязательное чтение перед реализацией

- `01-commerce-model-router.md` — выбрать правильный коммерческий режим;
- `02-conversion-and-information-architecture.md` — построить путь от входа до подтверждения;
- `03-domain-and-state-model.md` — не допустить декоративной корзины и клиентской «истины» о цене;
- `04-page-blueprints.md` — выбрать набор страниц и секций;
- `05-checkout-payments-and-fulfillment.md` — оплата, вебхуки, идемпотентность, доставка и запись;
- `06-pizzeria-blueprint.md` или `07-service-booking-blueprint.md` — отраслевой сценарий;
- `08-seo-legal-and-trust.md` — SEO, доказательства и локальный юридический gate;
- `09-motion-performance-and-accessibility.md` — безопасная выразительность;
- `10-agent-build-prompt.md` — готовое задание агенту;
- `11-quality-gate.md` — критерии готовности.

## Что этот модуль запрещает

- подменять каталог бесконечной главной страницей;
- показывать цену, скидку, наличие, рейтинг, срок доставки или свободный слот без источника данных;
- доверять итоговой цене, скидке и доступности, рассчитанным только в браузере;
- требовать регистрацию до покупки, если бизнес-ограничение не доказано;
- скрывать обязательные сборы до последнего шага;
- принимать оплату и считать заказ выполненным только по возврату пользователя на `success_url`;
- превращать запись на услугу с неизвестной доступностью в фальшивую корзину;
- использовать фальшивые отзывы, логотипы, таймеры, остатки или «заказали N человек»;
- добавлять тяжёлую анимацию в каталог, корзину или checkout без пользовательской пользы.

## Результат

После заполнения плана агент должен уметь собрать не «лендинг в стиле магазина», а проверяемую коммерческую систему: понятный выбор, честные условия, надёжное оформление, серверное подтверждение и восстановление после ошибок.
