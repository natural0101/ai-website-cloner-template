# Landing Section Patterns

Use this skill when the plan needs concrete section choices instead of abstract improvement notes.

## Required Reading

Read:

- `план разработки топового лендинга/16-section-pattern-library.md`
- `план разработки топового лендинга/09-landing-type-routing-matrix.md`
- active project `03-reference-board.md` and `06-section-by-section-upgrade-plan.md` if present

## Workflow

1. Identify the page type and section jobs.
2. Pick a pattern for each major section.
3. Record the choice in `13-section-pattern-selection.md`.
4. Convert each pattern into:
   - visible result;
   - motion purpose;
   - asset requirement;
   - component source;
   - mobile fallback;
   - risk/QA check.
5. Reject patterns that are impressive but do not support the offer.

## Rules

- One section pattern per section unless there is a clear reason to combine.
- No two adjacent sections should feel like the same layout family.
- Motion must be justified as hierarchy, storytelling, feedback, or state transition.
- If a pattern needs assets, add it to `08-component-and-asset-plan.md`.
- If a pattern needs a component source, check `11-component-source-registry.md`.
